# Agent Handoff (任务交接)

接手者（人或其他 Agent）只看这份账本就应该知道：现场是什么状态、哪些已经验证过、下一步做什么、什么不能碰。

## 流程

1. 运行快照脚本，拿到已填好事实的草稿：

   ```bash
   <本技能目录>/scripts/handoff-snapshot.sh [--repo <dir>] [--commits 5]
   ```

   它会填入分支、HEAD、未提交文件、最近提交、要先读的项目文件（`AGENTS.md`、`docs/current.md`、`.local/plan/*.md`），以及 `.local/run/pi/` 里还在运行或结果还没读取的委派任务。

2. 补全尖括号占位的部分：目标名称、已完成结果、验证状态、卡点、下一步、关键约束。这些需要判断，脚本给不了。
3. 按场景输出：直接回复给用户，或写入 `.local/plan/handoff.md`。

## 写好账本的要点

- **验证状态只写实际跑过的**：接手者会据此决定跳过哪些检查，把"计划跑"写成"已通过"会直接导致回归。没跑的写明原因。
- **未提交文件要说明去留**：否则接手者可能当成垃圾清掉，或者误提交。
- **下一步要能立刻执行**：写"运行 X 并修复 Y 处失败"，不要写"继续优化"。
- **关键约束只挑两三条**：挑最容易被新会话无意破坏的，比如"不要改动公共 API 签名"。
- 如果 `docs/current.md` 已经完整承载了这些状态，账本只需指向它，并补充它没覆盖的现场信息。

草稿结构可以按任务调整，但上面几类信息不要缺。
