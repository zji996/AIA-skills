# 主控长时间自主推进

适用于已获授权的一批工作；主控持续取任务、收结果、审查合入，直到触发停止条件。下文 `D=<本技能目录>/bin/delegate`。

## 留下可接续的待办

待办放在仓库的忽略目录，例如 `.local/backlog.md`，确认该目录已被忽略；分“进行中 / 待做 / 待确认”。每轮取最上面一项，派发时记任务名和 run id，完成后更新结果、验证与下一步。上下文被压缩后先读待办，再用 `status --json` 核对运行和已结束任务，凭文件接续。

## 保持唤醒

工作仍在推进时，主控每次结束回复前至少保留一个后台 `$D wait <run>`；宿主支持逐行事件时用 `$D wait --stream`。任务完成会唤醒主控，接到通知后处理结果并挂下一次等待。使用宿主的后台机制，单独 shell `&` 不保证通知。

等门禁或长命令时，后台直接跑命令本身（或 `$D lane`）；不要写 `until ! pgrep -f <模式>` 轮询，模式会匹配轮询 shell 自己。

Monitor 有过期时间，到期要重挂。已有等待者覆盖的任务再 `wait` 会立即退出 76；这表示通知仍给原等待者，不代表任务完成。核对等待者与任务状态，收取已结束的结果；原等待者退出、锁释放后才能重挂，不要反复等待同一活等待者占用的任务。

## 隔离写入与合入

写入任务一律 `--worktree`，源工作区留给主控 `apply`。同仓库串行合入，审 diff 后按任务提交，复用同事 commit 的说明；不要把多项工作的改动混成一个提交。

改写后手动合入的任务，提交后立即 `$D clean <run> --force`；自动检测只认完全包含，改写后可能仍显示部分包含。

每合入几批量一次源仓库的构建目录；它不在 `clean` 的范围内，超过自定阈值时按 [清理与磁盘占用](cleanup.md) 的“源仓库的构建缓存”处理。

委派只跑定向验收，每批合入后主控经 `$D lane` 跑一次全量门禁。墙钟性能断言失败先单独重跑，基准测试不要和门禁共用一个数据库；并行任务的外部测试状态也需由仓库测试入口隔离。

## 先审计，再解除阻塞

先派只读审计走完整流程，留请求、id、代码行等证据。阻塞项优先修，再复走曾被阻塞的步骤；不能用“前一步已失败”代替对后续步骤的验证。

## 停止与汇报

连续两轮没有有效进展、只剩需所有者确认的项，或门禁失败无法定位时停下。更新待办，汇报做了什么、怎么验证的、待确认什么。不 push、不发布，除非所有者已授权。
